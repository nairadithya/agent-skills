### Authoring or modifying a skill

1. Read Pi's `docs/skills.md` and use the Agent Skills format.
2. Validate frontmatter, relative file references, and skill names. Test structural behavior when a reproducible test exists.
3. Keep the skill concise. Remove rules that do not change a decision. Link structural sources rather than copying their details. Fix broken skills in the same task unless the user asks for a separate change.

Pi does not provide a built-in `create-skill` authoring skill. Draft and validate the skill directly. Apply `/skill:technical-writing` and `/skill:unslop` to prose.

**Reply:** summarize the skill, key design decisions, and validation.
